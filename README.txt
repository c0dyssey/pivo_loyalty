ПРОГРАММА ЛОЯЛЬНОСТИ — ПИВНОЙ МАГАЗИН
=====================================
Правило: каждые 6 оплаченных литров ЛЮБОГО пива = 1 литр любого пива бесплатно (общий счёт клиента).
Какое пиво отдать в подарок, выбирает клиент; оно не обязано совпадать с купленным.
Литры разных напитков складываются в один счёт. По напиткам статистика ведётся отдельно (что куплено, чем отдан подарок).

ЗАПУСК (Windows)
1. Установите Python 3 с python.org (галочка "Add Python to PATH"). Больше ничего ставить не нужно.
2. Запустите start.bat. Окно не закрывайте: пока оно открыто, сайт работает.
3. ПЕРВЫЙ РАЗ откройте на самом ПК https://localhost:8443 и задайте PIN (один PIN на магазин).
4. СЕРТИФИКАТ, ОДИН РАЗ (чтобы не было предупреждений ни на ПК, ни на телефоне).
   Программа сама создаёт свой центр сертификации (data/cert/ca.crt) и выпускает им сертификат сайта.
   - Windows: запустите install-cert.bat (подтвердите окно "Да"), перезапустите браузер.
   - iPhone: откройте в Safari https://192.168.x.x:8443/ca.crt (адрес из окна программы; на этом шаге предупреждение
     ещё будет: «Показать подробности» -> «посетить веб-сайт») -> «Разрешить» -> Настройки -> «Профиль загружен» ->
     «Установить». Затем Настройки -> Основные -> Об этом устройстве -> Доверие сертификатам -> включите
     «Pivo Loyalty Local CA». Эти же шаги есть в разделе «Настройки» сайта.
   Сертификат сайта продлевается автоматически (при смене IP или за 30 дней до конца срока), переустанавливать ничего
   не нужно. Папку data/cert не удаляйте: ключ центра там; если удалить, ca.crt придётся поставить заново.
5. PWA можно открыть на телефоне с GitHub Pages. В репозитории c0dyssey/pivo_loyalty выберите Settings ->
   Pages -> Deploy from a branch -> main -> /docs. Перед публикацией выполните `python build_pages.py`.
   Адрес приложения: https://c0dyssey.github.io/pivo_loyalty/. GitHub Pages содержит только файлы приложения,
   база и клиентские данные остаются на ноутбуке.
6. На iPhone подключитесь к Wi-Fi магазина, откройте PWA, укажите адрес ноутбука из окна программы
   (например https://192.168.x.x:8443) и войдите по PIN.
7. Работает только HTTPS на порту 8443. Не пробрасывайте этот порт из интернета; разрешайте его только
   в частной сети Windows. Камера QR работает только по HTTPS.
8. Windows спросит про доступ в сеть: разрешите для "Частной сети".

НАПИТКИ — ФАЙЛ settings.json (открывать Блокнотом)
Каждый напиток — одна строка в списке "drinks":
  { "id": "weissburg-lager", "name": "Вайсбург Лагер", "emoji": "🍺", "color": "#d97706" },
- name  — название на плитке (обязательно)
- emoji — значок (необязательно, по умолчанию 🍺)
- color — цвет плитки #rrggbb (необязательно, подберётся сам)
- id    — внутренний код напитка, латиницей. ПО НЕМУ хранится история клиентов.
          Не меняйте id у существующих напитков! Название (name) менять можно свободно.
          У нового напитка id можно не писать: он создастся из названия.
- "active": false — спрятать напиток из продаж (накопленные клиентами литры сохранятся).
Можно писать просто строкой: "Новый сорт". Запятые между строками обязательны, последняя строка без запятой.
Сохранили файл — обновите страницу на телефоне. Если в файле ошибка, сайт покажет её в «Настройки» и
продолжит работать со старым списком.

КАК РАБОТАТЬ
- Поиск: последние цифры телефона или фамилия. Или кнопка «Сканировать QR» (камера внутри сайта).
- QR клиента содержит только его код (без имени, телефона и адреса сайта). Работает только в этой программе.
  Клиент сохраняет картинку QR в телефон. Не получилось отсканировать: кнопка «Сфотографировать QR» или поиск по номеру.
- На плитке каждого напитка у клиента: сколько литров он купил этого пива и сколько подарка им отдано (🎁). Счётчик «До подарка» общий.
- Покупка: плитка напитка -> объёмы (+0,5 / +1 / +1,5 / +2 / +3) -> «Подтвердить покупку».
  Когда общий счёт дошёл до 6 л — сразу предложение списать бесплатный литр (решает клиент).
- Списание подарка: список, как у покупки. Выберите пиво, нажимайте +0,5/+1/+1,5/+2 или «Весь остаток», добавьте другое пиво,
  затем «Подтвердить списание». В сумме не больше доступного. Одна операция может включать несколько разных напитков.
- Фамилия необязательна: достаточно имени и телефона.
- Список покупки внизу не перекрывает страницу: она прокручивается до конца истории.
- Отмена: кнопка «Отмена» у ЛЮБОЙ операции в истории, с подтверждением. Если отменяется покупка, из-за которой
  уже списан подарок, сайт покажет это в окне подтверждения и отменит и списание.
- Меню ☰: статистика магазина, «Все покупатели» (полная таблица по каждому клиенту), настройки.

ДАННЫЕ, НАДЁЖНОСТЬ И ВОССТАНОВЛЕНИЕ
- data/data.json — вся база (формат JSON). Каждая операция пишется сразу: временный файл -> fsync -> атомарная замена.
  data/data.json.prev — предыдущая версия (на одну операцию назад), страховка на случай сбоя диска.
- Повтор запроса безопасен: у каждой операции свой request_id, он хранится в базе (30 дней).
  Нажали «Подтвердить» второй раз после обрыва связи или перезапуска сервера — дубля не будет, сайт покажет
  «уже была записана». Один и тот же ID для другого запроса сервер отклоняет.
- data/backups/ — копия каждый день (хранится 30), каждая копия проверяется. Свежая копия за сегодня обновляется раз в час.
  Копию на второй носитель (флешка/другой диск) вы делаете сами: копируйте папку data целиком.
- При запуске база проверяется. Если файл повреждён: оригинал сохраняется в data/corrupt/, молчаливого отката
  НЕТ, сайт переходит в режим «только чтение», все изменяющие операции блокируются с понятной ошибкой.
  Восстановление: на ПК магазина откройте https://localhost:8443, введите PIN, выберите версию (.prev или копию)
  и подтвердите. Подтверждённые операции, которые есть в выбранной версии, сохраняются; сайт покажет, сколько операций
  и клиентов вернётся. Пустая база поверх повреждённой не создаётся никогда.
- data/events.log — журнал событий (запуск, ошибки записи, восстановления).
- Сайт доступен только в Wi-Fi магазина. Не пробрасывайте порт 8443 на роутере.
- Закрепите IP компьютера в роутере (резерв DHCP), иначе адрес для телефона изменится
  (сертификат привязан к IP; при смене IP он выпустится заново сам, доверие к центру сертификации сохраняется).
- Автозапуск: Win+R -> shell:startup -> положите ярлык на start.bat.
- Забыли PIN: удалите data/config.json и откройте сайт на ПК, задайте новый (клиенты сохранятся).

ОФЛАЙН-РЕЖИМ И СИНХРОНИЗАЦИЯ (iPhone)
- Откройте сайт в Safari по HTTPS, войдите с PIN один раз, затем выберите «Поделиться» -> «На экран Домой».
  Оболочка приложения (HTML/CSS/JS/QR-декодер) кэшируется Service Worker; ответы API и бизнес-данные в кэш Service Worker не попадают.
- Клиенты, напитки и локальные операции сохраняются в IndexedDB браузера: хранилища customers, products, operations,
  outbox и sync_metadata. Приложение запрашивает у браузера постоянное хранилище, если API браузера это поддерживает.
  Не очищайте данные сайта, пока в меню «Настройки» есть ожидающие синхронизации операции.
- Без связи доступны поиск по ранее загруженным клиентам, регистрация клиента, покупка и списание подарка.
  Изменение карточки клиента и отмена операции требуют подключения к серверу. Баланс считается на телефоне как
  предварительный; окончательно операцию проверяет сервер.
- Каждая локальная операция получает UUID, постоянный ID устройства, последовательный номер и базовую версию сервера.
  Операция и запись outbox сохраняются одной IndexedDB-транзакцией. Повторные запросы используют тот же UUID;
  очередь не очищается при ошибке, неопределённом результате или конфликте. Повтор выполняется автоматически
  при возвращении сети, с экспоненциальной задержкой до 5 минут. Сервер регистрирует только одно устройство.
- После восстановления связи клиент отправляет очередь, удаляет только подтверждённые операции и затем получает
  серверные изменения. Курсор меняется только в той же IndexedDB-транзакции, которая применяет полученные данные.
  Конфликтные операции остаются на телефоне; в «Настройки» можно посмотреть их количество и экспортировать
  ожидающие операции в JSON для аварийного сохранения.
- Для надёжной работы откройте PWA онлайн хотя бы один раз после установки и выполните вход. Не очищайте данные
  Safari и не удаляйте PWA, пока outbox не пуст. Если телефон сообщает о нехватке места, освободите место вручную;
  приложение не удаляет клиентские данные и очередь автоматически.

API СИНХРОНИЗАЦИИ И ХРАНЕНИЕ
- Для GitHub Pages PWA хранится в папке docs/. Исходники интерфейса — static/; после их изменения
  обновите docs/ командой `python build_pages.py` и отправьте изменения в ветку, опубликованную Pages.
- В настройках Pages выберите origin `https://c0dyssey.github.io` (это уже разрешено по умолчанию).
  Для другого домена или владельца Pages задайте переменную окружения PIVO_ALLOWED_ORIGINS на ноутбуке:
  список HTTPS origins через запятую, без путей и завершающего слеша. Не используйте `*`.
- Между GitHub Pages и ноутбуком работает HTTPS CORS с bearer-токеном (токен хранится в IndexedDB на телефоне;
  сторонние cookies не нужны). Установите и включите доверие CA ноутбука на iPhone до подключения.
- Успешная работа требует, чтобы браузер iPhone разрешил локальной сети доступ к ноутбуку. Зафиксируйте
  локальный IP ноутбука в настройках роутера, чтобы адрес не изменился. Если используете браузер с Private
  Network Access preflight, сервер разрешает его только для origin из PIVO_ALLOWED_ORIGINS.
- Все синхронизирующие запросы требуют авторизации; для GitHub Pages используется bearer-токен:
  GET /api/sync/status — серверный курсор, зарегистрированное устройство и конфигурация;
  POST /api/sync/register — однократная регистрация device_id;
  POST /api/sync/push — до 50 операций за запрос, отдельное подтверждение/ошибка на каждую;
  GET /api/sync/pull?since=<cursor> — изменения, клиенты, конфигурация и новый курсор.
- Поддерживаемые офлайн-типы: register, purchase и redemption. Payload содержит клиентские поля регистрации
  или список {drink, liters}. Покупки и списания проверяются действующими серверными правилами лояльности.
  Повтор UUID с тем же payload возвращает прежний результат; изменённый payload отклоняется. Записи синхронизации
  не удаляются по стандартному 30-дневному TTL request_id.
- Авторитетная база остаётся data/data.json. В ней одним атомарным JSON-снимком хранятся клиенты, журнал операций,
  настройки напитков, ID обработанных запросов и устройство синхронизации. Поэтому операция и её дедупликация
  фиксируются вместе; запись выполняется во временный файл с flush/fsync, затем os.replace(), предыдущая версия
  остаётся в data/data.json.prev. Сервер сериализует изменения одним LOCK. Отдельная SQLite/облачная БД не используется.
- Сервер слушает HTTPS-порт 8443 и принимает только loopback/private/link-local IP-адреса. Оставьте роутер без
  перенаправления порта 8443 из интернета; разрешайте доступ в брандмауэре только для частной сети магазина.
- Передайте все ожидающие операции на сервер и дождитесь пустой очереди перед сменой или сбросом телефона.

ОФЛАЙН-ПРОВЕРКА НА ТЕЛЕФОНЕ
- После установки один раз откройте приложение онлайн, войдите и дождитесь завершения синхронизации, чтобы браузер
  сохранил оболочку и настройки товаров. Затем отключите Wi-Fi/сеть и проверьте поиск по уже загруженному клиенту.
- Для проверки офлайн-покупки используйте отдельного тестового клиента и обычную тестовую операцию; закройте и
  снова откройте приложение до подключения сети. Убедитесь, что запись и баланс остались на телефоне, а в настройках
  есть ожидающая операция. Включите сеть и проверьте, что очередь очистилась и на сервере появилась ровно одна покупка.
- Не проверяйте повторные нажатия на реальных продажах: повторная отправка одного сохранённого operation_id безопасна,
  но два отдельных нажатия создают две разные операции.

БЕЗОПАСНОСТЬ РЕПОЗИТОРИЯ
- Игнорирование data/ и settings.json защищает только будущие добавления. Ранее добавленные файлы остаются в старых
  Git-коммитах и могут быть доступны каждому, кто имеет доступ к истории репозитория. Удаление их из текущей версии
  не стирает историю. Не выполняйте force-push и не переписывайте историю без согласования с владельцем репозитория.
- Считайте ранее опубликованные ключи сертификата скомпрометированными. Чтобы явно создать новый локальный CA,
  остановите сервер и запустите `python rotate_certificate.py`, затем введите `ROTATE CERTIFICATE`. Скрипт не запускается
  автоматически, проверяет остановку сервера, не изменяет базу клиентов или PIN, и оставляет предыдущие публичные
  сертификаты в data/cert.previous-<время>. После этого запустите сервер, переустановите новый ca.crt на каждом
  доверенном устройстве и включите доверие к новому CA в iOS. На Windows запустите install-cert.bat повторно.
- Смените PIN отдельно через меню «Настройки» на доверенном устройстве. Серверный PIN не меняется скриптом ротации
  сертификата. Не удаляйте data/ и не сбрасывайте pairing для очистки Git-истории: это не требуется и может повредить
  рабочую базу или оставить офлайн-операции несинхронизированными.
- Перед включением GitHub Pages выполните `python build_pages.py`. Сборка публикует только файлы из allowlist и
  завершается ошибкой, если в docs/ остались неожиданные или чувствительные файлы.
